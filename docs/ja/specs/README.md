# 仕様書

このディレクトリには、大きめの変更に対する feature spec や workflow spec を置きます。

## spec を書く条件

次の変更では spec を書いてください。

- 複数モジュールにまたがる
- 利用者に見える挙動を変える
- データ契約を変える
- 段階的移行が必要になる
- 実装前に合意形成が必要になる

## 命名規則

内容が分かるファイル名にします。例:

- `synthetic-pipeline-v2.md`
- `real-data-import-service.md`
- `cli-unification.md`

## レビュー方針

大きな変更の spec は、実装前にレビューされるべきです。目的は共同開発者間の曖昧さを減らすことであり、軽微な変更に形式だけを増やすことではありません。
